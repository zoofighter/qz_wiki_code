# 위키 운영 가이드

## Obsidian 기본 설정

Settings에서 다음 항목을 권장한다.

- Files and links → Default location for new notes: 지정된 폴더
- Files and links → Default location for new attachments: `99-첨부파일`
- Files and links → Use Wikilinks: 활성화
- Core plugins → Templates: 활성화
- Templates → Template folder location: `90-템플릿`
- Editor → Properties in document: Source 또는 Visible
- Files and links → Automatically update internal links: 활성화

## 노트 작성 순서

1. 기존 노트를 검색하여 중복 여부를 확인한다.
2. `90-템플릿`에서 목적에 맞는 템플릿을 삽입한다.
3. 한 문장 요약과 학습 목표부터 작성한다.
4. 최소 실행 예제를 직접 실행한다.
5. 관련 노트를 wikilink로 연결한다.
6. 해당 과목 인덱스에 링크를 추가한다.
7. 공개 가능 여부를 `publish` 속성에 표시한다.

강의 메모, 웹클립, LLM 원본 응답처럼 검증 전 자료는 완성 노트에 바로 넣지 않는다. 비공개 `02-Raw/` 영역에서 Raw 전용 템플릿으로 수집한 뒤 검증하고 정제한다.

## 노트 상태

| 상태 | 의미 | 완료 조건 |
|---|---|---|
| `seed` | 아이디어 또는 짧은 메모 | 핵심 질문이 적혀 있음 |
| `growing` | 학습 중인 노트 | 설명과 실행 예제가 있음 |
| `evergreen` | 반복 검토된 노트 | 링크, 예제, 오류 설명이 충분함 |

## 링크 작성

- 기본 링크: `[[C 시작하기]]`
- 별칭 링크: `[[Java 클래스와 객체|클래스와 객체]]`
- 제목 링크: `[[위키 운영 가이드#노트 작성 순서]]`

새 노트는 최소한 하나의 인덱스에서 들어오는 링크를 받고, 본문에서 관련 노트로 나가는 링크를 하나 이상 갖도록 한다.

## 추천 커뮤니티 플러그인

처음에는 코어 기능만 사용한다. 필요가 분명해졌을 때 다음 도구를 검토한다.

- Dataview: 속성 기반 목록과 대시보드
- Linter: frontmatter와 Markdown 형식 통일
- Git: vault 버전 관리 보조

플러그인을 설치하기 전에 유지보수 상태, 권한, 모바일 호환성, Quartz 출력 호환성을 확인한다.
